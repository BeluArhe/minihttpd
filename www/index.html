minihttpd

Servidor HTTP/1.1 de alto rendimiento en C

Contexto del Proyecto

Este servidor fue desarrollado para la materia de Computación Distribuida (EPN), destacando la importancia de una arquitectura concurrente y eficiente. A diferencia de los modelos tradicionales que revisan las conexiones una por una con complejidad lineal O(n), minihttpd utiliza el mecanismo epoll de Linux. Su bucle de eventos actúa como el hilo maestro que monitoriza los canales de red y devuelve instantáneamente qué descriptores están listos, logrando una complejidad altamente optimizada de O(1).

Arquitectura y Decisiones de Diseño

  • Conexiones Persistentes y Búferes: El servidor gestiona búferes internos para almacenar peticiones que llegan fragmentadas en múltiples paquetes por la red. Mediante la búsqueda del delimitador \r\n\r\n, determinamos el fin de las cabeceras.
  • Soporte Estricto GET: Atendemos únicamente el método GET, bloqueando cualquier intento de inyección de cuerpo para prevenir ataques de Request Smuggling.
  • Seguridad de Memoria: Se reemplazaron funciones inseguras (como strcpy) por alternativas seguras con límites de tamaño para evitar desbordamientos de búfer.
  • Mitigación de Path Enumeration: Para evitar que un atacante descubra la estructura interna del sistema operativo mediante el escaneo de rutas, cualquier intento de acceso indebido responde sistemáticamente con un 404 Not Found en lugar de un 403 Forbidden, ocultando la existencia real del recurso.
